# 0004 仕様の元はリポジトリ、Confluence は写し。行き来はMCPで

- 状態: 採用（0003 を置き換える）
- 日付: 2026-11-14

## 背景

仕様を Confluence だけに置くと、エージェントは作業のたびに外へ取りに行き、コードと仕様が別々に変わる。
リポジトリだけに置くと、開発者以外が見に来ない。
Confluence のAPIを直接呼ぶ方法は、社内のネットワークや認証の都合で届かない環境がある。MCPのサーバーは、利用者の認証でつながる。

## 決めたこと

- 仕様は `docs/specs/` の Markdown を元にする。コードと同じプルリクエストで変える。
- Confluence とのやり取りは、`.mcp.json` に登録した Atlassian のMCPサーバーで行う。書き込みも取得もMCPのツールを使う。
- MCPのツールを呼ぶかどうかはモデルが決めるので、呼び忘れは終了前のフックで止める。フックは台帳（`.sync.json`）と Markdown の sha256 を比べるだけで、通信はしない。
- 一致の確認で、ページの全文を取得しない。全文はそのままコンテキストに入り、ページの数だけ費用がかかるため。
  1. 手元の台帳で、変わったファイルだけを対象にする（トークンは使わない）
  2. ページの版の番号だけを取得し、最後に書き込んだ版のままなら一致とする
  3. 版が進んでいたページだけ、2つの版の差分を取得する
- ページの末尾に Markdown の sha256 を書いておく。台帳をなくしたときに、全文を比べずに対応を作り直せる。

## 結果

仕様を直すと、終了前のフックが未反映を指摘し、エージェントが書き込む。レビューの指摘で直したときも同じ。
ふだんの確認は、版の番号の取得だけで終わる。全文に近い量を取得するのは、誰かが画面で書き換えたページだけになる。
