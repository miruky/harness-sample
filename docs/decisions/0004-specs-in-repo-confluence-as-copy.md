# 0004 仕様の元はリポジトリ、Confluence は写し。行き来はMCPで

- 状態: 採用（0003 を置き換える）
- 日付: 2026-11-14

## 背景

仕様を Confluence だけに置くと、エージェントは作業のたびに外へ取りに行き、コードと仕様が別々に変わる。
リポジトリだけに置くと、開発者以外が見に来ない。
Confluence のAPIを直接呼ぶ方法は、社内のネットワークや認証の都合で届かない環境がある。MCPのサーバーは、利用者の認証でつながる。

## 決めたこと

- 仕様は `docs/specs/` の Markdown を元にする。コードと同じプルリクエストで変える。
- 基本は、push のたびにCIが `tools/docs_sync.py` でAPIから書き込み、ページに書いた sha256 と全文で一致を確かめる。モデルを通さないので、トークンはかからない。
- APIが届かない環境では、`.mcp.json` に登録した Atlassian のMCPサーバーで書き込む（`/sync-specs`）。MCPのツールを呼ぶかどうかはモデルが決めるので、呼び忘れは終了前のフックで止める。
- MCPで書き込んだときも、最後に `docs_sync.py verify-body` で、APIのときと同じ照合を必ず通す。
- MCPでの確認では、全ページの全文を取得しない。全文はそのままコンテキストに入り、ページの数だけ費用がかかるため。
  1. 手元の台帳で、変わったファイルだけを対象にする（トークンは使わない）
  2. 書き込んだページだけ、全文を取得して照合する
  3. 書き込んでいないページは、版の番号だけを取得し、最後に書き込んだ版のままなら一致とする
  4. 版が進んでいたページだけ、2つの版の差分を取得する

## 結果

仕様を直して push すれば、レビューの指摘で直した分も含めて、Confluence の写しが最新になる。
MCPの経路でも、全文を取得するのは書き込んだページと、誰かが画面で書き換えたページの差分だけになる。
