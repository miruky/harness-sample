# ハーネスを育てた記録

エージェントの失敗や人の手直しを、ハーネスのどこへ戻したかの記録です。新しいものを上に足します。
1件につき、起きたこと、原因、戻した先、確かめた結果を書きます。

- 「評価」は `evals/` の5つの課題を、小さいモデル（Claude Haiku 5.5）と大きいモデル（Claude Opus 5.5、推論の強さは high）に3回ずつ解かせた結果です。数字は15回のうちの回数で、元の記録は `evals/results/` にあります。
- 「対話」は、Claude Code と Codex を端末で使っていて起きたことです。
- 原因は4つのどれかに決めます。知らなかった、知っていたが守らなかった、確かめられなかった、やってはいけなかった。

## 16. 照合のスクリプトが、正しく書き込んだページを不一致と判定した

- 起きたこと: 対話なしの実行。MCPで仕様を5件書き込ませたところ、`<予約ID>` という文字を含む1件だけ、照合が通らなかった。照合がこの文字をタグと取り違えて消していた。エージェントは原因の行まで挙げたうえで、照合を通さずに台帳へ記録することはせず、直してよいかを聞いて止まった。
- 原因: 確かめられなかった。照合のテストに、山かっこを含む仕様がなかった。
- 戻した先: `tools/docs_sync.py`。Markdown のまま書かれたページは、タグを取り除かずに比べる。山かっこを含む仕様のテストを足した。
- 確かめた結果: 5件とも照合を通る。

## 15. 新しく足したテストが、サンドボックスの中で動かなかった

- 起きたこと: 対話なしの実行。Confluence をまねたサーバーを使うテスト5件が、エージェントのサンドボックスの中ではエラーになった。ローカルのポートを開けなかったため。エージェントは報告の中で、今回の変更とは関係がないと断ったうえで知らせてきた。
- 原因: 確かめられなかった。13番と同じで、検査のコマンドがサンドボックスの中で動かない作りになっていた。
- 戻した先: `.claude/settings.json` の `sandbox.network.allowLocalBinding` を `true` にした。
- 確かめた結果: サンドボックスの中で `make check` が最後まで通る（86 passed）。

## 14. CIが、最初の push で落ちた

- 起きたこと: リポジトリを GitHub に置いた最初の実行が、5秒で失敗した。`astral-sh/setup-uv@v10` というタグが存在しなかった（あるのは `v10.3.3` のような細かい番号だけ）。ワークフローはエージェントが書いたもので、番号は確かめていなかった。
- 原因: 確かめられなかった。CIの設定は、push するまで動かす場所がない。
- 戻した先: `.github/workflows/ci.yml` の番号を `v10.3.3` に直した。`AGENTS.md` や検査には何も足していない。1回きりの間違いで、次に起きてもCIが自分で知らせるため。
- 確かめた結果: 直したあとの実行は通った。

## 13. Codex が make check のたびに承認を求めた

- 起きたこと: 対話。Codex のサンドボックスは作業フォルダの外へ書き込めない。uv はホームのキャッシュを開こうとして失敗し、Codex は `make check` を実行するたびに「サンドボックスの外で実行してよいか」を聞いた。
- 原因: 確かめられなかった。検査のコマンドが、サンドボックスの中では動かない作りだった。
- 戻した先: `Makefile`、`.codex/config.toml`、`.claude/settings.json` で `UV_CACHE_DIR=.uv-cache` を指定し、キャッシュを作業フォルダの中に置いた。Claude Code のサンドボックスに足していた、ホームのキャッシュへの書き込み許可は消した。
- 確かめた結果: `codex sandbox -- make check` が承認なしで通る。

## 12. フックが止めた回数が、次の依頼まで残った

- 起きたこと: 対話。終了前のフックは、直らないまま回り続けないよう3回で止めるのをやめる。その回数を数えるファイルが、変更を元に戻したあとも残り、同じセッションの次の依頼では最初から止めなくなった。気づいたのはエージェントで、返答の最後に指摘があった。
- 原因: 確かめられなかった。フックの数え方を確かめるテストがなかった。
- 戻した先: `.agents/hooks/verify_before_stop.py`。入力の `stop_hook_active` が偽のとき（新しい依頼の最初の終了）は、回数を0から数える。

## 11. フックを抜ける書き方と、サンドボックスを外す経路があった

- 起きたこと: 対話。`cat .env` はフックが止めた。`python3 -c "print(open('.env').read())"` はフックを通り抜け、サンドボックスが `Operation not permitted` で止めた。エージェントは、サンドボックスを外して実行する指定がまだ使えることを指摘した。
- 原因: やってはいけなかった。フックは文字列の照合なので、書き方を変えると通る。
- 戻した先: `.claude/settings.json` の `sandbox.allowUnsandboxedCommands` を `false` にした。秘密と実データを読ませない役は、サンドボックスの `denyRead` が受け持つ。フックは理由を返すために残す。

## 10. 評価用の受け入れテストを見て、実装を合わせた

- 起きたこと: 対話。stats コマンドを足す依頼で、エージェントは `git ls-files` で `evals/tasks/acceptance_stats.py` を見つけ、中身を見て、通るまで実装を合わせた。
- 原因: やってはいけなかった。評価用のテストを開かない、とはどこにも書かれておらず、止めるものもなかった。答えを見て作った実装は、評価に使えない。
- 戻した先: `.claude/settings.json` の deny と、サンドボックスの `denyRead`。git の履歴から取り出す書き方は両方を抜けるので、`.agents/hooks/guard_bash.py` にも規則を足した。フックの差分は `/harness-retro` を呼んでエージェントに作らせ、人が確かめて当てた。
- 確かめた結果: 次のセッションでは、エージェントが `git ls-files | grep -v '^evals/tasks'` と自分から避けていた。

## 9. 編集を見張るフックが、1回も動かなかった

- 起きたこと: 対話。Opus 5.5 は、ファイルの書き換えをほとんどシェルのコマンド（Python の短いスクリプトなど）で行った。フックは編集ツール（Edit、Write）だけを見ていたので、保護したいファイルの確認も、層の向きの検査も呼ばれなかった。
- 原因: 確かめられなかった。エージェントがどのツールで編集するかを、決めつけていた。
- 戻した先: 層の向きの検査は、Bash のあとにも動かす（変更されたファイルは git から拾う）。人が確かめてから変えるファイルは、終了前のフックで変更の有無を確かめ、サンドボックスの `denyWrite` にも入れた。

## 8. deny が .env.example まで拒否した

- 起きたこと: 対話。`.env` の中身を聞かれたエージェントは、指示どおり開かず、代わりに `.env.example` で設定の名前を示そうとした。deny の `Read(./.env.*)` がそれも拒否した。
- 原因: やってはいけなかった、の逆。止める範囲が広すぎて、正しい行動まで止めた。
- 戻した先: `.claude/settings.json` の deny を `.env`、`.env.local`、`.env.*.local` の列挙に変えた。

## 7. 設定に書いても、英語の報告が残った

## 6. 実データの柵が、気をつけている操作を止めた

- 起きたこと: 評価。`bookings.json` という文字を含むコマンドを全部止める規則を入れたところ、小さいモデルは15回で14回、大きいモデルは10回止められた。止めたのは、`--exclude=bookings.json` や `git check-ignore bookings.json` のように、実データを避けるための操作だった。
- 原因: 起きていない失敗のために柵を作った。素の状態から数えて、実データが書き換えられた回は1回もない。
- 戻した先: 規則を消した。`AGENTS.md` の1行と、Read と Edit の deny だけを残した。
- 確かめた結果: 規則を消したあとも、実データが書き換えられた回は0のまま。

## 5. 編集のたびのリントが、書きかけに反応した

- 戻した先: 編集のあとは層の向きだけを確かめ、整形とリントは終了前のフックへ移した。整形は黙って直す。
- 確かめた結果: フックが止めた回数は15回で0になった。
