# 失敗をハーネスへ戻す

起きたこと: $ARGUMENTS

同じ失敗を次のセッションで繰り返さないために、原因を1つ選び、置き場所を1つ決める。
決まりごとを足す前に、いまあるものを直せないかを先に確かめる。

## 手順

1. 何が起きたかを事実で書く。説明がなければ、このセッションのやり取りと `uv run python tools/harness_stats.py` の結果から拾う。
2. 原因を次から1つ選ぶ。
   - 知らなかった: 必要な情報が、エージェントの見える場所になかった
   - 知っていたが守らなかった: 書いてあるのに、従わなかった
   - 確かめられなかった: 正しいかどうかを自分で確かめる手段がなかった
   - やってはいけなかった: 取り返しのつかない操作ができる状態だった
3. 置き場所を下の表から1つ選ぶ。上の行ほど軽く、下の行ほど確実に守られる。判断がつかなければ軽いほうから試す。
4. `docs/harness-log.md` の先頭に1件足す（日付、起きたこと、原因、置き場所、変えたファイル）。
5. 変更を提案する。`.agents/hooks/` と `.github/workflows/` は自分で書き換えず、差分を返答に書いて人に渡す。
6. 足した決まりが古い決まりと重なるなら、古いほうを消す。`uv run python tools/check_harness.py` で行数と参照を確かめる。

## 置き場所の決め方

| 原因 | 内容 | 置き場所 |
|:--|:--|:--|
| 知らなかった | どの作業にも関係する短い事実 | `AGENTS.md` に1行 |
| 知らなかった | 特定の場所だけの決まり | `.claude/rules/` に `paths` 付きで |
| 知らなかった | 何手もある手順 | `.claude/skills/` |
| 知らなかった | 判断の理由 | `docs/decisions/` |
| 知っていたが守らなかった | 機械で判定できる | リンターか `tools/check_layers.py`。直し方を出力に書く |
| 確かめられなかった | 動かせば分かる | テスト、`make check` |
| やってはいけなかった | 実行前に止めたい | `.claude/settings.json` の deny か `.agents/hooks/` |

2回続けて守られなかった文章の決まりは、文章を強くするのではなく、表の下の行へ移す。
